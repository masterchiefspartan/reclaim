# PRD Intake Checklist

#

# Use before handing a PRD to Cursor for autonomous implementation.

## Scope

- [ ] One feature or one user flow only
- [ ] No hidden requirements outside the PRD
- [ ] Explicit "out of scope" list

## Requirements Clarity

- [ ] Functional requirements are numbered
- [ ] Non-functional requirements are listed
- [ ] Acceptance criteria are concrete and testable
- [ ] Edge cases are called out

## Technical Details

- [ ] File list is explicit (create/modify)
- [ ] TypeScript interfaces defined
- [ ] API contracts documented
- [ ] Data flow described

## UX/UI

- [ ] Loading state defined
- [ ] Empty state defined
- [ ] Error state defined
- [ ] Success state defined
- [ ] Accessibility requirements listed (if needed)

## Dependencies

- [ ] External services listed
- [ ] Required env vars documented
- [ ] Database collections and rules noted

## Security

- [ ] Auth requirements specified
- [ ] Input validation requirements listed
- [ ] Sensitive data handling described

## Done Definition

- [ ] Test strategy described
- [ ] Manual verification steps listed
- [ ] Rollback plan referenced
